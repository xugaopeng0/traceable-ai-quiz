# Proposal

## Why

当前仓库只有选题文档，尚无平台代码、接口和可执行验收约束。开发前需要统一两名成员的领域边界、来源与权限规则、自检协议和评测口径，避免生成线与质量线各自实现后无法对接。

## What Changes

- 定义工程骨架优先的任务顺序、课程平台固定版本导入边界、模块架构、开发规范和部署验收。
- 定义基于已发布讲义的组卷任务、数量与难度配额、持久化执行及失败恢复。
- 定义核心题型的结构化输出、规则与语义自检、重复检测和有限重生成。
- 定义来源定位、字符区间、代次有效性、权限与隐私约束。
- 定义教师审核、编辑、发布、重生成及 JSON/Markdown 导出的完整流程。
- 定义出题与问答评测数据、人工标注、对比实验和回归门禁。
- 当前只完成规划与工具配置；实施任务保持未完成，业务代码与部署留待 apply。
- Scenario 统一写明前置条件、操作、可观测结果；显式覆盖参数非法、无权限、资源不存在和依赖不可达四类失败路径，约束使用具体数量、状态码和超时。
- 补齐产品交互与视觉基线、严格筛选、逐资源附件授权、受控整批导入、16 例 AI 快速集、健康停机、备份删除和一键完成门禁；这些是核心链路的工程约束，不增加网页导题、学生作答或自主工具执行能力。

## Capabilities

### New Capabilities

- `platform-foundation`：固定基础版本、认证与班级授权、模块集成边界。
- `generation-runs`：范围选择、配额、长任务、重试与幂等。
- `question-quality`：题型结构、证据校验、语义检查与去重。
- `question-provenance`：来源定位、字符语义、代次失效与并发保护。
- `teacher-workbench`：任务进度、审核编辑、题卷发布与导出。
- `quality-evaluation`：评测集、指标、标注、实验与门禁。
- `api-contract`：统一接口、错误、并发控制与契约校验。
- `delivery-operations`：部署、安全配置、检查和交付证据。

### Modified Capabilities

无。本仓库尚无已交付主规约；课程仓库作为基础依赖，不在本变更中修改。

## Impact

未来影响 frontend、backend、数据库迁移、worker、Compose 和评测脚本；新增题目、来源、尝试、自检、题卷、评测及审计数据。沿用 MySQL/Qdrant，不新增消息中间件或独立 Python Web 服务。

## Non-goals

不实现学生作答、作业布置、评分成绩、OCR、多选简答、自动章节识别、自动知识点聚类。已有问答只纳入质量回归，不扩展聊天产品功能。此规划不承诺任何尚未实测的质量数字。
